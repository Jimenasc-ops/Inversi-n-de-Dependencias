# Inversi-n-de-Dependencias
//Lo que busca este principio es que las partes principales del programa no dependan directamente de los detalles de como se hace cada tarea, sino de una idea general o interfaz. Primero se crea la clase EnvioRecibo que sirve como una plantilla o regla abstracta con la funcion EnviarRecibo. De ahí se crean las clases EnviarApp y Enviar Email, que son las que realmente hacen el trabajo y definen como se manda el recibo en cada caso. Despues en la clase AdmProducto, ara hacer la compra no se le pone directamente si es por correo o por aplicacion, sino que recibe cualquier tipo de EnvioRecibo, haciendo que AdmProducto no le importa como se envía, solo sabe que se va a enviar.El main solo creo la forma de envio que se quiere y se la pasa al administrador
